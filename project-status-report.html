personal-workbench 的下一句定义，
应该是通用强辅助工作台 / Workflow OS。

这不是推翻 V3.4 之前成果的改写，而是对现状更准确的命名。当前产品已经把任务中心、文件总线、常驻页面、终端、本地工具与卡片舱收进同一个工作壳里。新的页面叙事要表达的是：这些已完成能力不是某一条专用流程的临时拼装，而是在为一个可承接多种工作流的 Workflow OS 打基础。

当前事实
V3.4 已交付，能力已跨过原型期
叙事转向
从单流程工具，升级为通用能力底座
路线纪律
先收紧风险面，再扩展能力面
一句话判断
产品要摆脱“只服务一种工作流”的表述，但不能制造“要重写一遍”的误解。

新版页面必须同时讲清两件事：一是为什么旧叙事已经不够，二是当前完成的能力会被保留、升格并继续收紧，而不是被替换掉。

Why The Turn

为什么必须从单一流程叙事转向 Workflow OS

旧叙事的问题不是“它错了”，而是“它已经太窄了”。现在的代码和已交付能力，已经证明这个产品不是只会替一种业务流程减负的专用工具，而是正在形成一个可以复用到多种任务类型的统一工作台底座。

问题
继续用单流程表述，会把真实能力说小
叙事偏窄

如果页面仍把 personal-workbench 描述成某一种工作流的专用助手，那么任务中心、常驻页面、终端、本地工具接入、文件总线这些已经完成的能力，看起来会像为当前任务临时缝出来的配件，而不是可迁移的底座。

证据
现有实现已经覆盖任务、页面、文件与动作闭环
已验证

V3 到 V3.4 的演进并不是功能堆砌，而是在持续把工作入口、产物流转、字段填写、状态写回和本地执行面统一到一个壳里。这说明产品价值来自“统一工作流承载”，而不是某一条业务线本身。

转向后的收益
保留已完成能力，同时为更多 workflow 留出接口
可扩展

当页面叙事改成通用强辅助工作台 / Workflow OS，现有能力就能被重新组织成通用模块。以后新增一种工作，不需要重写工作台，只需要在既有能力块上定义新的任务模型与动作链。

Capability Blocks

未来页面要围绕五个能力块，而不是围绕单条流水线组织

这五个块不是凭空抽象出来的概念，而是对当前已完成能力的重新命名。它们把现有功能抬升成可复用的产品语言，同时保留“已经能工作”的现实基础。

Task

任务：承载任何 workflow 的主对象

  • 保留现有任务中心、任务卡、任务舱与五步流水线。
  • 保留 V3.2 的 txt 导入和 V3.3 的状态写回，把任务进出系统的链路收在一起。
  • 后续把当前固定流程提升为可配置任务模板，而不是丢掉已有任务能力。
File

文件：下载、上传、裁切、归档、回写的产物总线

  • 保留 V3.1 的下载捕获、文件托盘、上传注入与图片裁切。
  • 保留任务文件夹上下文，把产物与任务绑定而不是散落到系统里。
  • 后续把这些能力抽象成所有任务都能复用的文件与产物流转层。
Page

页面：常驻网页、本地视图、终端与扩展的统一承载层

  • 保留常驻 webview、多标签、分屏、地址栏与扩展面板。
  • 保留底部终端、CLI 常驻标签和本地桌面应用嵌入能力。
  • 它们共同构成 Workflow OS 的表面层，不再只服务当前业务页面。
Agent

智能体：计划、执行、验证、审查的强辅助协作者

  • 当前已存在的人机协作现实，是用户在工作台里调度 Claude、Codex、Hermes 与 GitHub 协作协议。
  • 卡片舱已经证明“把 AI 产出压缩进用户动作链”是有效的协作方式。
  • 后续 Agent 层不是另起炉灶，而是把现有协作关系提升成一等能力块。
Action

动作：复制、注入、拉起、检查、回写等可编排操作

  • 保留卡片舱逐字段复制、平台字段试注入、文件注入、打开文件、定位文件、运行本地工具等现有动作。
  • 这些动作已经存在于产品中，只是还没有被统一表达成动作层。
  • 后续新增 workflow 时，优先复用动作而不是重写交互细节。
Four Directions

页面只展示四个未来方向，避免路线分叉失焦

未来方向必须严格收敛到四个，并且用现有能力当作起点。这样页面既能表达演进空间，也不会把读者带回“什么都要重做”的误解里。

01
方向 1
通用任务引擎
最高优先级

把当前只服务一类任务的流程，提升成可配置的任务模板系统：不同任务类型可以拥有自己的阶段、输入、产物、完成条件与回写规则，而不是继续把所有变化写死在一条流水线上。

02
方向 2
文件与产物总线
持续收紧

把下载捕获、上传注入、文件托盘、裁切与状态写回，从当前任务的有效实现，收紧成所有 workflow 都能接入的统一产物流转层，让文件逻辑不再跟单一业务绑死。

03
方向 3
Agent 协作层
后置落位

未来可以让计划、执行、验证、审查与 handoff 的智能体共享任务、文件、页面与协作上下文，但这一层必须建立在稳定的任务模型与动作层之上，不能先扩面再补底座。

04
方向 4
自动化动作编排
关键桥梁

把打开页面、切换标签、复制字段、文件注入、运行命令、拉起本地应用、写回状态与触发检查这些能力显式化，编组成可复用 action chain，让工作台从强辅助更进一步走向 Workflow OS。

Recommended Sequencing

推荐推进顺序必须明确写成 1 → 2 → 4 → 3

路线顺序不是展示装饰，而是后续决策约束。页面必须公开表达：先稳住任务模型，再收紧产物总线，再把动作编排抽出来，最后才让 Agent 层自然落位。任何跳步，都会把复杂度提前引进系统。

Roadmap Rail
Step 1

1 · 先做通用任务引擎

先解决“系统如何承载不止一种任务”的问题，否则所有新增能力都只是在单流程上继续打补丁。

Step 2

2 · 再继续收紧文件与产物总线

文件上下文决定很多 workflow 能否闭环。没有稳定产物流转，任务模型再通用也会卡在落地执行面。

Step 4

4 · 然后抽出自动化动作编排

动作层负责把当前已经有效的复制、注入、运行、回写能力组合起来，为更多 workflow 复用，而不是在每个场景里重复造轮子。

Step 3

3 · 最后让 Agent 协作层落位

只有当任务、文件、动作三层稳定后，Agent 才能真正承担计划与执行，而不是放大底层的不稳定性。

为什么不是先上 Agent
因为系统现在最需要的是稳定边界，不是更大的控制面。
先做 1
把“任务是什么”抽清楚，后续所有 workflow 才有一致宿主。
再做 2
把“产物怎么进出系统”收紧，才能支撑跨任务复用。
再做 4
把“系统如何做动作”编排出来，才谈得上自动化。
最后做 3
Agent 层吃的是底座成熟度，不应反过来要求底座临时适配它。
Preserve And Tighten

已完成能力要被保留并升格，同时继续收紧现实薄弱点

新叙事的重点不是宣告“旧版本结束”，而是告诉读者：当前已有成果都进入下一阶段，只是从专用实现升格为通用底座。页面要明显写出哪些东西被保留，哪些地方要继续收紧。

当前成果 在 Workflow OS 中的新角色 本轮页面要强调的处理方式
常驻页面、多标签、分屏、扩展、终端 统一页面层（Page Surface） 保留并抬升为通用承载层，不再只被叙述成当前流程的外壳。
任务中心、任务舱、五步流水线、txt 导入/写回 任务层（Task Engine）的现成基础 保留并逐步抽象，不暗示“旧任务系统要被重做”。
下载捕获、文件托盘、上传注入、图片裁切 文件与产物总线（File / Artifact Bus） 保留并继续收紧可靠性，让现有能力成为通用产物层。
卡片舱、字段复制、试注入映射 动作层与特定 workflow 插件的先行样板 保留其产品价值，同时明确它是可复用动作层的起点，而不是一次性功能。
要保留的判断
不是重写

页面必须反复传达：当前成果方向正确，只是表达层与抽象层需要升级。

不是降级

从单流程叙事转向 Workflow OS，不是把现有深度优化变浅，而是把深度优化变成可复用模块。

要继续收紧的现实
可靠性

上传链路、文件分类、竞态与回归边角问题，仍然是产品可信度的一部分，不能因为叙事升级而被跳过。

状态对齐

页面、roadmap 与真实代码状态必须同步，否则产品方向会被过时文档重新拉回旧叙事。

Review Impact

对抗性审查如何改变路线纪律：先收紧风险面，再扩展能力面

adversarial-review 的价值，不只是列出风险点，而是给路线图加了一个顺序约束：在继续扩展 Action 与 Agent 之前，必须先把已经暴露出来的高风险面收紧到可控范围内。页面需要把这个原则直接写出来。

路线规则：tighten risky surfaces before expanding capability surfaces

第一轮审查已经把高风险边界画出来，包括 Electron 主进程权限边界、loopback 本地 HTTP API、token 暴露链路、上传/下载自动化路径，以及文件系统与本地应用执行面。它们决定了后续功能扩展不能只看“能不能做”，还要先看“风险有没有收口”。

这意味着什么

方向 1 和方向 2 可以继续推进，因为它们主要在抽清任务模型、收紧产物流转；但方向 4 和方向 3 每向前一步，都会扩大自动化与协作控制面，所以必须建立在更严格的权限、边界与验证纪律上。

页面要给出的结论

产品未来可以更强，但不能更冒进。下一阶段的正确姿势不是盲目扩更多 agent 或动作，而是在保留现有价值的同时，把高风险表面先缩窄、标定并验证清楚。
