让多个 AI 像一个团队一样
协同干活的开源项目

AI Collab Hub 用一个普通的 GitHub 仓库 + 一堆人人能看懂的 Markdown 文件， 让不同电脑、不同工具里的多个 AI 助手共享记忆、交接工作、互相配合。

先打个比方：想象一个小公司里有几位员工—— Antigravity 是产品经理（想方案、写规格），Codex 是程序员（写代码、跑测试）。 他们不在同一个房间，甚至不在同一台电脑上，怎么配合？

答案是：公司里放一块共享白板（GitHub 仓库）。每个人上班先看白板（git pull）， 干完活把进展写回白板（git push）。白板上有任务清单、当前状态、交接便签、决策记录—— 这就是整个项目的核心思想：AI 之间不直接"共享脑子"，而是共享清晰、可读、可追溯的工作记录。
PART 1 · 项目是什么

一个项目，三大块内容

打开这个仓库，你会看到很多文件夹和文件，但其实它们只属于三大块：

📋

① 协作协议（文件总线）

一套用 Markdown 文件定义的"AI 团队工作制度"：状态放哪、任务放哪、怎么交接、怎么记录决策。 核心文件是 PROTOCOL.md，配套目录有 status/、tasks/、handoff/、inbox/ 等。

🧪

② Hermes 智能体

一个"提示词仿真与评估系统"（server.py + hermes_agent.py + 网页界面）。 你丢给它一份教学任务文档，它自动生成 AI 导师提示词，还会派一个"模拟学生"去试聊，打分不合格就自动优化。

🖥️

③ 个人工作台

personal-workbench/ 里的一个 Windows 桌面应用（用 Electron 开发）。 把浏览器页面、终端、任务管理、文件流转、周报、Token 统计全部装进一个窗口， 目标是"打开工作台 = 完成全部工作"。

这个仓库既是"制度手册"（协作协议），又是"车间"（两个真实可运行的软件）。 两个软件都是按这套制度、由多个 AI 分工协作开发出来的——所以它本身就是这套协议的活案例。

PART 3 · 协作协议 / 文件总线

AI 团队的"共享白板"是怎么运转的？

所谓"文件总线"，就是一组约定好用途的文件夹。任何 AI（或人）都按同一套规则读写它们， 信息就能在不同 AI、不同电脑之间流动，而且全程人类可读、可追溯。

📊

status/current.md 必读

全项目的"值班表 + 晨会纪要"：当前目标、谁在负责、最近进展、下一步、已知风险。任何 AI 开工前第一个读它。

📥

inbox/ 收件箱

按来源分三个文件：from-user.md、from-antigravity.md、from-codex.md。想到什么新点子、新需求，先丢进来，处理完就移入"已处理"。

✅

tasks/ 任务看板

三个文件就是三列看板：todo.md（待办）→ active.md（进行中）→ done.md（完成）。改任务状态 = 把任务段落从一个文件"搬"到另一个文件。

🤝

handoff/ 交接区

AI 之间"交班"的便签。比如 antigravity-to-codex.md 就是产品经理把方案递给程序员。每张便签固定包含：日期、摘要、当前状态、重要文件、决策、待解决问题、请对方下一步做什么。

⚖️

decisions/ 决策记录

重大技术选择写在这（业内叫 ADR）。比如"为什么用 Markdown 而不是数据库做协作协议"，让后来者不用猜"当初为啥这么干"。

📚

docs/agents/ AI 说明书

给 AI 看的领域文档：任务看板怎么用（issue-tracker）、状态怎么流转（triage-labels）、项目核心概念在哪查（domain）。

PART 4 · Hermes 智能体

自动写提示词、自动试聊、自动打分的"教练工厂"

使用场景：你需要在教学平台上搭建"AI 导师"（比如引导学生完成实训任务的对话机器人）。 手写提示词又慢又难保证质量。Hermes 把这件事变成：上传任务文档 → 一键得到打磨好的提示词。

4.1 它由三个文件组成

🌐

server.py Web 服务

用 Python 的 FastAPI 框架搭的小型网站服务器，跑在本机 127.0.0.1:8000。它是"前台接待"：接收网页发来的请求，转交给大脑处理，再把结果送回网页。

🧠

hermes_agent.py 核心大脑

全部智能逻辑都在这：分析任务、生成提示词、模拟对话、评分、优化，共 6 个模块（下面详细讲）。它通过调用大语言模型 API 来完成这些工作；没配 API 时自动降级为"模拟模式"，方便无网调试。

🖼️

index.html + static/ 网页界面

浏览器里看到的三栏操作面板：左栏填任务文档和参数，中栏回放模拟对话，右栏展示评分、卡片方案和最终提示词（每个字段都带"一键复制"按钮）。

4.2 对外提供哪些接口？

接口方法干什么用怎么实现的
/ GET 返回网页主界面 直接把 index.html 文件发给浏览器（FileResponse），同时把 /static 目录挂载出去提供 CSS/JS。
/api/start-harness POST 核心接口：接收任务文档，启动完整的"生成 → 仿真 → 评估 → 优化"流程，返回全部结果（JSON） 接收表单参数：任务文本 text 或上传文件 document（支持 txt/md/docx/pdf，用 python-docx 和 pypdf 解析出纯文本）、 合格分数线 threshold、学生人设 student_persona、阶段跳转词 transition_word。 先把输入存到 debug/ 目录便于排查，然后调用 HermesAgent.run() 跑完整流水线，最后把结果对象转成 JSON 返回。
"接口"就是软件之间约定好的"服务窗口"。网页（前端）想让 Hermes 干活，不是直接翻它的代码， 而是往 /api/start-harness 这个窗口递一张"申请表"（表单数据），窗口里的人（server.py）处理完再把"办理结果"（JSON 数据）递回来。

上面 5 个模块都不自己"思考"，思考工作统一交给这个模块调用大语言模型 API（读取 config.json 里的密钥和模型名）。 API 挂了或没配置？自动切换到内置"模拟模式"返回预设内容，保证系统永远能跑通、能演示。

🎯 阶段跳转词是什么？

训练分多个阶段（如"任务理解 → 方案制定 → 复盘总结"）。约定 AI 导师在学生达标时只输出一个暗号（如"下个阶段"）， 系统检测到暗号就自动切换到下一张卡片。每张卡片还可以有自己独立的暗号。

PART 5 · 个人工作台

把所有工作装进一个窗口的桌面应用

personal-workbench/ 是一个用 Electron（可以理解为"给网页套一个桌面软件外壳"的技术，VS Code 也是这么做的） 开发的 Windows 应用。它解决的问题很朴素：用户每天要在 10+ 个网页、企业微信、终端、文件夹之间反复横跳——干脆全塞进一个工作台。

🗂️

基础壳：常驻标签页 + 终端

每个网页用一个常驻 webview 标签承载，切换只是"隐藏/显示"而不重新加载——所以登录状态、表单内容、滚动位置都不会丢。 支持左右/上下分屏、Chrome 扩展加载，底部还内置了真正的 PowerShell 终端（用 node-pty + xterm.js 实现）。

🚦

任务驱动：五步流水线

任务中心是默认首页。每个任务卡走固定五步：准备 → 本地测试 → 评估上传 → 捕获报告 → 完成， 进度环和状态栏实时同步。还能解析桌面的「待做任务.txt」一键导入任务，改完状态再一键写回 txt——双向闭环，两边不再各记各的。

🚌

文件总线：文件自动"归巢"

执行任务时自动创建任务专属文件夹。期间所有下载自动落进该文件夹；网页要上传文件时，自动弹出任务文件供你选择注入（技术上用 CDP 调试协议拦截文件选择框）； 图片可一键裁掉底部水印。文件不再散落在"下载"目录里找不到。

🃏

卡片舱：告别逐字段誊写

Hermes 的产出保存为 cards.md 后，工作台自动解析成结构化卡片（名称/轮次/描述/开场白/提示词）。 往平台填表时逐字段一键复制，"流式模式"还会自动高亮下一个待填字段——把 30 多次"选中-切页-粘贴"变成 30 次无脑点击。

📈

周报中心 + Token 统计

从任务数据一键生成周报快照，可编辑、可导出 HTML/Markdown/DOCX、可直接复制粘贴进企业微信文档。 Token 统计则展示本机 Codex / Claude Code 的用量和成本——数据来自一个独立的 Rust 小助手程序（sidecar），工作台只负责展示。

🧮

作业批阅方差（集成工具）

点击后按需启动一个 Python + FastAPI 侧车服务，提供作业批阅轮询、均值/方差计算、Excel 导出。 侧车只监听本机端口 + 随机令牌鉴权，数据隔离存在用户目录，不进代码仓库。

🔒 安全设计（为什么小白也该关心）

工作台里跑着很多第三方网页，所以做了明确的安全边界：网页拿不到你电脑的 Node.js 能力（contextIsolation 隔离）； 会话令牌只发给本机地址，绝不发给外网网站；文件路径做了"穿越攻击"防护；Cookie、Token、个人任务数据一律不提交到 Git 仓库。

"sidecar（侧车）"是个形象的叫法：主应用是摩托车，旁边挂个小车斗装专门的工具。 Token 统计的 Rust 程序、作业批阅的 Python 程序都是独立的小车斗——各自独立运行， 主应用通过本机通信（JSONL 消息或 HTTP）跟它们说话，谁坏了都不拖累谁。

线索二：用户的日常工作流（工具在跑）

Hermes 和个人工作台联手，覆盖了用户"搭建能力训练任务"的端到端 10 步流程：

1
领任务：企业微信查看本周任务，整合到桌面「待做任务.txt」→ 工作台一键导入为任务卡。
2
收文档：拿到任务文档，放进任务专属文件夹（工作台自动创建）。
3
开工位：工作台里打开常驻网页标签 + Hermes 页面，登录态都还在。
4
生成方案：任务文档交给 Hermes（走 /api/start-harness 接口）→ 自动分阶段、生成提示词、模拟学生试聊、评分优化。
5
填平台：Hermes 产出保存为 cards.md → 工作台卡片舱解析 → 逐字段一键复制填进公司平台。
6
做封面：AI 生成封面图 → 工作台托盘一键裁掉底部水印 → 填到平台。
7
填标准：评价标准同样从卡片舱一键复制。
8
测试评估：浏览器插件测试 → 测试对话自动下载进任务文件夹 → 上传评估页时自动注入这些文件。
9
改到通过：不合格？评估报告被自动捕获归档 → 一键把对话和报告路径灌回 Hermes → 修改 → 循环直到通过。
10
收尾：任务状态在工作台标记完成 → 一键写回「待做任务.txt」，闭环结束。
注意分工：Hermes 负责"动脑"（生成和验证提示词），工作台负责"跑腿"（文件搬运、页面切换、复制粘贴）， 而它俩之间通过文件（任务文件夹、cards.md、dialogue.json、评估报告）传递成果——这正是"文件总线"思想在用户侧的延伸。
